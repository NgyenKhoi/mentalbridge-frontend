# MB-596 product journey metrics

The real protected `/admin/dashboard` workspace now renders the backend-owned `product-journey-metrics-v2` projection through an authenticated same-origin BFF. The journey is a focused panel composed with the current operations workspace rather than a competing dashboard route. An administrator can select 7, 30, or 90 days and refresh the current window. Loading, complete, partial-source, unsupported-fact, dependency-error, and retry states are explicit; stale counts are cleared after a failed refresh.

The UI renders aggregate counts plus only the explicitly approved cohort progress rates. USER activation is bounded to USER accounts registered in `[from,to)` and verified before `to`; Consultation confirmation/completion is bounded to appointments requested in `[from,to)` and reaching the corresponding milestone before `to`. Care activity remains factual counts with no invented cross-stage rate. The UI does not calculate clinical or recovery outcomes, does not turn unavailable sources into zero, and describes every rate as product activity rather than effectiveness or causation. The exact authoritative response window and as-of instant are visible, while source versions and per-source as-of instants remain available under the collapsed technical disclosure.

Focused production-workspace, component, and BFF tests cover `/admin/dashboard` rendering, exact window forwarding and response matching, ADMIN authentication, unavailable-source presentation, unsupported Support Guide usage, stale-data clearing, and removal of the previous hard-coded journey values. A mismatched authoritative response window fails closed. The frontend Identity and Consultation contract snapshots and generated TypeScript types are synchronized with the backend OpenAPI sources.
