# MB-775 Mầm web release gate

Scope: web only. Tests, a measurement script and this evidence; no product behaviour, backend, contract, `.tsx` or `.css` change. Authority: `docs/ADR_MAM_RIVE_V1_CONTRACT.md` (gate and flag `:182`, flag-off behaviour `:434`, the three production conditions `:466-476`, all met 2026-10-27).
Run on 2026-10-28 against the production standalone build of base `e44b2954` (MB-774 merged), flag toggled by environment only.

**Verdict: the web gate passes with the findings below. Nothing blocks turning `MAM_WEB_ENABLED` on for web USER dock routes. The flag stays off by default until the owner flips it per the rollout plan.**

## Findings

1. **Flag off still ships the dock host code.** `app/providers.tsx` imports `MamDock` statically, so the dock component is in the shared root bundle with the flag off. Only the Rive runtime chunk (55,560 B), `.riv`, `.wasm` and `.svg` are flag-gated or lazy. The JS delta above therefore understates Mầm's total code. Acceptable for the gate; a dynamic import would remove it if bundle size matters. Resolved by MB-781 ([`mb-781-mam-dynamic-dock.md`](mb-781-mam-dynamic-dock.md)); the numbers in this file stay the MB-775 record.
2. **Idle animation costs about 7 points of one core.** In the recorded run the animated dock raises idle CPU from 2.51% to 10.03% on this machine; the static dock route adds 0.15 points (4.09% to 4.24%), and the hero flight adds about 3 more while it plays. Nothing pauses the loop for `saveData` or low power (no such handling exists), and offscreen or background-tab behaviour was not measured. Recommendation: a follow-up story for low-power handling if low-end phones matter; the owner can still ship because users can turn motion off.
3. **Console noise on WASM loss.** A blocked `.wasm` writes about 10 error lines once from the Rive runtime and then stops. The page and static Mầm are fine. No action.
4. **No CSP.** The repository has none. When one lands, `script-src` needs `'wasm-unsafe-eval'` for the self-hosted Rive WASM, and `/mam/*` is same-origin only (verified above).
5. **No reachable dark theme in the USER shell.** The `:root[data-theme='dark']` tokens in `app/globals.css` repaint nothing on the dashboard. Mầm has no dark styling of its own.
6. **Observation, not Mầm:** `/resources` renders "This page couldn't load" when the Bingo request returns the fixture's unexpected body (seen when only the Home mocks were installed, flag on and off). Not investigated; the gate specs install the plan mocks.
7. The MB-774 evidence row "Dock disabled ... NOT_RUN as E2E" is now covered by `mam-flag-off.spec.ts`.

## Rollout plan

1. **Staging:** set `MAM_WEB_ENABLED=true` in the staging web runtime (the flag is read on the server at request time, no `NEXT_PUBLIC`, no rebuild) and restart the web process. Owner smoke on `/dashboard`, `/resources`, `/journal`, `/achievements`, `/support-guides`: dock appears, Help Now and page actions work, hide and motion controls persist, and on `/support-plan` one dock with no legacy Companion (MB-772; with the flag off the legacy Companion and no dock).
2. **Production:** after the owner confirms staging, set the same variable in production and restart. The repository only holds `.env.example` with `MAM_WEB_ENABLED=false`; the deploy configuration for staging and production lives outside it, so the owner or Codex applies the change there.
3. **Watch list for the first week:** web error rate and hydration errors on the five dock routes, requests for `/mam/*` returning non-200, page-load complaints on mobile, support contacts mentioning the character, and CPU or battery feedback (finding 2).

## Rollback

Set `MAM_WEB_ENABLED=false` (or remove it) and restart the web process. No rebuild, no data migration, no user action. Verified: after the restart no dock element renders on any dock route, no `/mam/*` request is made, page actions are unchanged, and users' stored preferences are left as they were, so turning the flag back on restores their choices.
